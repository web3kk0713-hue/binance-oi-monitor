# 币安 OI 监测

直接读取 Binance 官方合约 OI、标记价、指数价和美元换算汇率。按币汇总，结合可追溯供应量计算流通市值与 FDV，展示比较图、时间曲线与阈值提醒。

**网站：[GitHub Pages](https://web3kk0713-hue.github.io/binance-oi-monitor/)**

## 自定义变化监控

[变化监控页](https://web3kk0713-hue.github.io/binance-oi-monitor/?view=changes)独立填写 OI 和 FDV 的涨跌幅阈值，支持上涨、下跌、双向绝对值，以及同时满足／任一满足。默认过去5分钟，OI数量变化绝对值 ≥5%，FDV变化绝对值 ≥3%，同时满足。窗口可填1–10080整数分钟；参数应用后保存在当前浏览器。

- OI默认比较原始数量，可切换为包含价格影响的美元名义金额。两项各自计算涨跌幅，不是“新增OI除以FDV”。
- 起点取目标时刻之前最近的已知真实观测，最多早45秒；两项共用起止时刻。过期、合约组成变化、缺少源时间、零分母或历史不足均明确标记；不寻找更早的有利起点，也不补造七天历史。
- 页面列出命中、全部和无法判断的标的，支持搜索、排序、实际变化值与联动曲线。只判断端点净变化，不证明整个窗口连续；曲线缺口断开。本页条件尚不产生新的OS通知或关页推送。
- 显示本轮合约/OI/FDV覆盖率、缺失原因及限流冷却。失败轮可保留明确标记的“上次有效”金额，仅供参考，不用于本轮变化或告警。后台源码不等于已有常驻云端后台。见[采集恢复验收](docs/workflow/collector-reliability-acceptance.md)。

## 持仓与价格联动

变化监控和异常监控都置顶展示重点观察与当前标的数据带：数量 OI、价格、美元 OI、FDV、OI/FDV 名义占比、占比相对变化及百分点变化。变化页沿用自定义窗口；异常页固定 5 分钟。表格支持联动筛选和占比相对变化排序。

- 联动标签固定观察线为数量 OI 变化绝对值 ≥5%，价格“近乎不变”为绝对变化 ≤0.5%；与自定义 OI/FDV 命中条件分别显示。仅描述端点，不是统计异常、资金流入、实际杠杆或买卖信号。
- 占比相对变化为 `(末OI/末FDV) / (初OI/初FDV) - 1`，不是两个涨跌幅相除。固定供给时 FDV 与价格、占比变化与数量 OI 高度相关，不当作独立确认票。隐含供给变化超过0.01%会提示。
- 两页复用一个订单流采集器，展示合约/已核实现货最近完整5分钟主动买入、净主动成交及当前资金费率和周期。源时间及计价币分开标明，不假装与快照端点精确同步；预热、未覆盖、过期显示空值。
- 曲线补充价格与可切换的占比相对变化；事件回放明确标记旁边的“当前快照”，导出同时区分历史触发证据和当前持仓上下文。见[增量验收](docs/workflow/position-context-acceptance.md)。

## 异常事件工作台

### 当前 5 分钟方向建议

变化页的标的详情、表格以及异常页详情、事件列表新增“偏多候选 / 偏空候选 / 观望 · 暂不交易”。固定 5m，不随 OI/FDV 自定义筛选窗口改变；单独列出依据、现货确认、风险与撤销条件。

- `direction-v1`：同一合约连续实测的 OI 数量 ≥+5%，价格 >+0.5% 且主动买 ≥60% 为偏多候选；价格 <−0.5% 且主动买 ≤40% 为偏空候选。占比与成交差额须一致，但不是两份独立证据。减仓、横盘、冲突、缺数或过期不硬给方向。
- 现货仅同资产、同报价币、同闭合窗口确认。买占比 ≥55% 且价格上涨 / ≤45% 且价格下跌才算同向；明确反向撤销候选；未覆盖或中性标“待现货确认”。资金费率只提示风险，不当作方向票，未知周期不默认8小时。
- 这是一组**未回测的筛选启发式**，不是已验证的交易策略，不提供胜率、自动下单、入场价或止损价。当前建议不代表历史事件当时可见的建议；不读取事件未来结果进行判断。见[方向建议验收](docs/workflow/direction-acceptance.md)。

### 事件与证据

默认首屏为全市场事件列表与联动证据图，原 OI / FDV 表格与历史在「持仓估值」保留。

- 全市场合约 `aggTrade` / `kline_1m` 流持续接收，页面约5秒汇总；OI继续目标30秒采样。启动分批补齐360根官方分钟K线；预热最短约5分钟，配额保护、样本不足或缺口会延长，目录每小时更新。
- 1m / 5m K线、大额成交气泡、主动成交差（Delta）、分段累计成交差（CVD）、原始合约OI数量共用时间轴；缺口不连线。未收盘K线降低透明度，不用于方向事件。
- 大额成交：连续连接至少5分钟，此前至少1000个实际聚合成交；最近60分钟内最多10000条样本的P99.5与100000报价币取大值。阈值5秒缓存，单方向1分钟冷却。热点超量淘汰不会让市场永久无法预热。
- 持续买卖压力、放量突破/跌破、价量/OI背离、盘口变薄分别有可查看的触发证据。成交额基准为当前窗口之前最多60个完整、不重叠5分钟窗的中位数，至少12窗。具体参数固定在 `FLOW_RULES` / `flow-v1`，均为实验规则，没有收益或胜率承诺。
- 现货与标准深度：直连跟随所选币种，现货必须经官方目录核实；后台当前固定 BTCUSDT。其他后台标的深度留空，不宣称全市场覆盖。盘口使用快照加连续增量核对，标准深度不含RPI；价格移出可验证范围或增量断档时暂停该指标。
- 事件点击回放前后15分钟，查看原始证据、触发理由、失效条件，以及随后1/5/15分钟价格变化。变化以发现后第一个完整且按时收到的分钟收盘价为起点；缺口停止计算，不包含手续费、滑点及资金费，不是可执行策略回测。
- 分钟证据、事件、盘口采样与OI保留7天；从实际采集积累，并非上线即具备7天历史。浏览器小时分桶压缩、容量不足会明确报错；数据库独立 `flow_*` 表不改写旧OI记录。接口回放同时限制源时间与收到时间，不把事后补取的数据当成当时已知。
- 新事件有醒目页内提醒及用户已授权的系统通知；初次加载历史事件不轰炸。**订单流事件尚未接入关页 Web Push**；既有后台 OI/FDV Web Push 不变。

这里的“主动买卖”不是开多开空；`aggTrade` 不是一个完整大单或账户，不能据此识别鲸鱼身份或断言庄家出货。各市场保留原生报价币，现货与合约不混加。

## 两种运行方式

| | GitHub Pages 直连 | 独立后台 |
|---|---|---|
| 数据采集 | 打开的浏览器目标每30秒直接请求官方接口 | 常驻 Node 服务目标每30秒采集 |
| 历史 | IndexedDB：7天30秒观测，之后真实分钟观测至30天 | 数据库30天聚合观测，另保留7天逐合约原始值 |
| 页内提示 / 系统通知 | 页面运行期间支持，需用户授予通知权限 | 支持 |
| 关闭网页后采集和推送 | **不支持** | 配置 VAPID 后支持 Web Push |
| 数据来源可核查 | 来源面板含请求地址、原始数值及时间 | 同样保留来源证据 |

GitHub Pages 是静态托管，不能运行持续采集进程；GitHub Actions 的 schedule 最小间隔5分钟，不能当作本产品的30秒采集器。网站默认直连，无后台时会清楚显示运行边界，不会用静态示例或旧快照伪装实时数据。关闭页面、浏览器休眠、断网及接口限流会留下历史缺口。30秒是目标间隔，不保证每轮全币种完整；27秒预算及官方动态配额保护会主动停止超时/超额请求。30天是保留窗口，不代表首次打开就有30天数据。**当前未部署云端常驻后台。**

### OI / FDV 历史变化

- 时间范围为 5 分钟、1 小时、24 小时、3 天、7 天、30 天，默认 5 分钟；保存真实观测，不补造上线前历史。
- “涨跌幅”按同一有效起点对齐 OI、流通市值、FDV，避免数值量级差异掩盖变化；可切回美元金额。下图独立展示 OI / FDV 与 OI / 流通市值。
- 变化摘要显示 OI 与 FDV 百分比和美元差额，以及 OI / FDV 的百分点差（pp）。缺少起点、数据过期或分母为零时不伪报涨跌幅；历史不足时注明真实起点，不称为完整 3 / 7 天回报。
- 新数据按实际完成时间保存，同一分钟的两个30秒观测不会互相覆盖；断采不连线。每个历史点固化当时有效金额，后续供应量更新不重算旧 FDV。行情不完整时不记有效点，供应量超过 2 小时或映射未通过时仅保留有效 OI。浏览器7天以后的压缩只保留每分钟最后一个真实点，不移动时间戳。
- 旧版未记录供应量有效性标记的历史估值，保留原始存储但不再用于曲线或比较；新版本从有效采集点继续积累。直连数据可能被浏览器清理，连续 3–7 天监控仍需实际部署常驻后台。

### 5 分钟短线观察

- 原始数量：对 Binance `openInterest` 按明确合约倍率归一后求和；与美元名义 OI 分列。仅同一合约组成、时间一致、无采样缺口的真实30秒点参与5分钟变化。旧版分钟数据不能冒充新数量历史，缺少窗口时显示积累中。
- 选中币种时，连接 Binance 官方永续和已核实的同币种现货成交/最优买卖价流；只订阅当前标的。报价单位明确显示，USDT 不标成 USD。
- 主动买入占比按收到的成交额计算，`m=true` 是主动卖出。连续满5分钟、成交及报价均新鲜时才展示完整窗口；断线、页面休眠或缓存超限会重新积累。不是全市场资金流，也不是开多/开空金额。
- UI为行情表与标的曲线工作台；估值与数据列可切换，散点移至“市场分布”。OI/FDV阈值只代表风险，所有观察指标尚无扣费后收益验证，不构成买卖信号。

## 数据和计算

### 缺失与限流恢复

- OI 按 30 秒目标采样；缺失或尚未请求的合约优先、公平轮换。上游限流或本机配额保护期间暂停请求，界面显示冷却时间；刷新页面不会清除已知冷却。历史补取单独限额，保留主要额度给 OI。
- 本轮失败可显示带原始时间的“上次有效（非实时）”数值；它与本轮覆盖率分开，不作为新历史点、涨跌幅或告警输入。没有可靠旧值时仍显示空缺。供应身份/最大供应量不可靠时不补造 FDV。
- 缺失身份映射最多每 5 分钟重验；供应接口遗漏的资产有界重试，不反复抓取仍新鲜的成功项。正常供应量仍按小时刷新。
- 浏览器仅尽力共享同源限流状态，不能协调其他软件、设备或整个共享 IP；30 秒不是交易所服务保证。关闭网页后连续采集仍需真实部署常驻后台。验收范围见 [采集恢复验收](docs/workflow/collector-reliability-acceptance.md)。

### 指标口径

- 范围：Binance 当前交易中的稳定币保证金加密资产永续合约。排除交割、指数、传统资产和币保证金；无需 Binance API key，无交易接口。
- OI：`openInterest × markPrice × quoteUsd`，使用 decimal.js 运算，按可靠身份映射汇总同币不同合约。不会把多空两边再乘二。
- 价格：Binance 指数价，千倍等合约归一到每一枚币，再按 Binance assetIndex 换算美元。
- 流通市值估算：`每币价格 × circulating_supply`。
- FDV估算：`每币价格 × max_supply`。固定最大供应量口径，不直接混用不同供应商的 FDV 字段；没有可靠最大供应量时为缺失。
- 供应量：浏览器直连使用允许跨域读取的 CoinGecko 官方 API；后台对 BTC、ETH、NEIRO、PUMP 优先使用已核实 ID 的 CoinMarketCap 官方 API，其余使用 CoinGecko。每条记录明确标识来源。禁止凭同名或跨平台 slug 自动合并。供应源价格仅作负向一致性检查，偏差超过30%时估值留空、禁报；价格接近本身不是身份证据。供应量按小时刷新，并非每30秒重新审计；身份映射及供应量缺失、受限、陈旧时标记原因。
- 原始数据可以在所选币种的来源面板核查与导出；本项目不将供应商原始数据批量打包为公共数据集。

默认阈值：OI/FDV 达70%黄色、90%红色、100%强提醒。阈值可配置，同级默认30分钟冷却，升级即时提醒。只有完整、时间有效、身份确定且存在可靠FDV的记录可触发提醒。OI/FDV描述仓位名义规模与估值的关系，并非多空方向或保证金金额。

## 本地启动

需要 Node.js 24 和 pnpm 11。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

打开 `http://127.0.0.1:5178`。构建、测试和真实数据探测：

```sh
pnpm test
pnpm build
pnpm probe
```

`pnpm probe` 直接访问外部数据源，只输出覆盖率、耗时和有限示例，不创建假数据。测试里的固定样本仅用于验证计算和故障边界，不进入生产页面。

## GitHub 发布

推送到 `main` 后，GitHub Actions 自动测试、构建并部署 `dist/`。仓库 Settings → Pages 的 Source 需为 GitHub Actions。构建产物只包含前端，不包含数据库、推送私钥或数据供应商私钥。

## 常驻后台

### 工作台与手工持仓

主界面为“市场机会 / 我的持仓 / 风险提醒”。市场机会保留变化、异常和 OI 估值；指标旁的说明按钮支持鼠标、键盘和手机点按。方向候选提供灵敏、标准、严格、自定义参数，各档均未验证盈利能力。

“我的持仓”支持 USDT 线性永续手工记录。录入不启用提醒；系统以可核验同合约标记价及 ATR 提出波动距离草案，用户核对价格并确认计划后才监控。保护、止盈、移动保护与信号减弱均为提醒，不会下单或自动标记平仓。数量/盈亏是输入保证金和杠杆推算，未计手续费、资金费与滑点，不是账户真实仓位或强平预测。

**手工仓位及计划仅保存在当前浏览器的私密 IndexedDB，不上传 GitHub 或公共行情 API。关页/休眠可能漏过触线；连接行情后台也不等于已部署后台仓位监控。** 修改方案需重新确认；跨标签通过原子状态与通知队列去重。详细合同、性能与验收边界见 `docs/workflow/workbench-upgrade.md`。

### 行情服务部署

后端源码在 `server/`，支持 PostgreSQL 及本地 SQLite；部署配置见 `compose.yaml` 和 `.env.example`。必须从目标机器实测 Binance 是否可访问，不能通过地区绕过限制来承诺可用性。

只读 API：`GET /api/v1/history?assetId=binance:BTC&hours=168` 返回资产历史；`GET /api/v1/contracts/BTCUSDT/history?hours=168` 返回原始 OI/价格字符串和各自源时间、实际接收时间。订单流增加 `/api/v1/flow/snapshot`、`/api/v1/flow/events?marketKey=futures:BTCUSDT&limit=100`、`/api/v1/flow/history?marketKey=futures:BTCUSDT&hours=168`。历史从进程实际采集开始积累，不回填不存在的30秒点；事件 `before` 为发现时间游标，当前界面展示限量结果，不保证同毫秒多事件的无损逐页遍历。

1. 复制 `.env.example` 为 `.env`，配置数据库及允许访问的网页来源。
2. 在目标服务器以 Docker Compose 启动，或使用 Node 24 运行 `pnpm server`。
3. 通过 HTTPS 反向代理公开 API，在网页设置中连接后台地址。
4. 需要关闭网页后推送时，配置服务端 VAPID，并从网页点击启用通知。

不要把 `.env`、数据库、推送订阅地址或私钥提交到仓库。通知订阅是匿名的，浏览器保存删除/更新令牌；后台只允许已知推送服务的 HTTPS 地址，限制来源和调用频率。

Web Push 送达依赖联网、系统通知权限和浏览器后台行为，过期通知可能无法送达；服务端告警记录可以在恢复连接后查看。尚未部署或未配置推送密钥的后台，不会报告推送已启用。

## 技术与许可

React、Vite、ECharts、Fastify、PostgreSQL、decimal.js、idb、web-push。第三方依赖保留各自许可（ECharts Apache-2.0；web-push MPL-2.0），本项目未修改第三方源码。上游完整应用经比较后未采用，参见 `docs/workflow/baseline.md`。
