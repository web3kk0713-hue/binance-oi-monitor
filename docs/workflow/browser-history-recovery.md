# 纯网页历史恢复 — 2026-09-29

## 当前授权与范围

用户明确只用网页，并要求断线后拉历史。沿用 GitHub Pages / React / TypeScript / IndexedDB，不新增后台、云资源、依赖、账号或费用。此前 GitHub 发布授权保持不变。

本轮覆盖「异常监控」所选市场的普通历史图，按 1h / 24h / 7天可见区间补 1m K线和单合约 5m OI；不对全市场无差别拉七天。资产估值和变化监控的 30s 实测、FDV 仍沿用原有口径，不将不相容历史混进信号。

## 数据合同与隔离

- Binance `GET /fapi/v1/klines` 或已核实现货 `/api/v3/klines`，只保存已闭合分钟，保留 OHLC、成交额、主动买额及原生报价单位。源时间不改成补取时间。
- `GET /futures/data/openInterestHist` 的最小周期 5m，最多500条/页，官方保留最近1个月；本产品只拉最多7天。仅读取 `sumOpenInterest` 原生单合约数量，`FlowOi.source='rest-5m'` 标识来源，不读取其金额或流通量来推导 FDV。
- 官方说明：https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data
- 返回点保留实际 `receivedAt`；没有30s OI、历史FDV、盘口或完整大额成交事件的可核验来源时，保持空缺。
- REST回填只写历史归档，写入接口固定 `events: []` / `depth: []`。实时引擎额外拒绝 `source='rest-5m'` OI。历史事实不能倒推实时进场提醒或旧事件结果。
- `historical` 只表示普通行情图允许发起补拉；默认 `as-known` 为只读证据回放，二者的在途请求不合并。存储/图表继续限制 `receivedAt <= to/observedUntil`；后来补到的数据不会出现在更早的固定回放截止时间内。

## 恢复与性能

- 读本机记录立即返回；独立低优先级补取，最多一个网页历史工作并行。切市场、扩展/倒退范围时取消旧任务；模式卸载取消，定时图表读取跟进补取状态。
- 每轮最多6页，每页至多500条，20秒总预算；共享既有实时采集配额保护。正常30秒冷却，空页/失败/超时至少60秒，并遵守更晚的上游限流时间。
- 只请求真实缺口。最新格点尚未发布时保留缺口，但排除本轮已尝试区间，继续拉更早数据，避免永远卡在最新空页。
- IndexedDB沿用小时分桶、七天归档和幂等合并；已存在的首次可见闭合记录不被后续REST覆盖。数据库写入失败不显示补齐成功。
- 浏览器恢复 online 或变成可见时请求一次实时采集，遵守已有busy及cooldown检查，不开启额外循环。
- 图表分开显示实测OI蓝线与5m补取菱形点，不连线插值。状态显示补取中/缺口数量/失败原因/当前区间已补齐，换区间不借用旧状态。
