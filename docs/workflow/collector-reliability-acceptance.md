# 采集缺失与限流恢复验收

日期：2026-09-23。用户在已批准的 Binance OI 监控项目中要求“优化、继续”。本轮保持 React/TypeScript、Fastify、SQLite/PostgreSQL 及既有 GitHub Pages 发布路径，无新增依赖、账号、云资源或机器后台服务。

## 修改与边界

- 修复并发 418/429 后短冷却覆盖长封禁的问题，始终保留较晚截止时间。第一条限流错误即携带 retryAt；排队请求再次检查冷却，手动刷新不绕过。
- 共享请求权重预算维持交易所声明上限的 80%；历史补取限制在 20%，为 OI 等主采集请求保留容量。仅是本进程/浏览器同源的配额保护，不是整个共享 IP 的协调器。
- 浏览器保存公开的冷却和当分钟权重信息，刷新时恢复；禁用存储则退化为会话内保护。不同标签页尽力合并最大值，不承诺跨标签页原子预留。
- 未采集、失败的 OI 优先并公平轮换，持续坏合约不能永久挤占其他合约。合约目录正常缓存 15 分钟，新上市币进入目录后独立补元数据。
- 未解析身份最多 5 分钟重验；供应接口遗漏行有界补取，成功资产仍按自己的真实获取时间到期，不因补漏延后所有资产。max_supply 本来未知时不当作漏返回，也不以 total_supply 冒充。
- Snapshot.lastGood 是独立展示层：同资产、同合约集合和倍率、有效源时间、最多 7 天的真实完整观测。数值附“上次有效 HH:mm:ss（非实时）”；不改写 assets、coverage、源字段或历史。当前供应身份证据不足时继续屏蔽旧估值。
- 两张页面显示本轮覆盖率、冷却和保留旧值数；变化、命中、排序与提醒仍依据原始本轮记录。UI 保持现有克制布局和颜色，警告直接可见、详情折叠。
- 后台数据库增量增加重试、尝试和最后成功时间；失败轮不冒充成功。失败观测可以留下原始空缺，并单独携带旧显示值。重启仍遵守冷却，同一 30 秒槽内多个调度器不重复失败重试。

## 验证

- 本机全量 `pnpm test`：26 个文件、348 项通过；`pnpm build`、`git diff --check` 通过。原 ECharts 渲染包 >500kB 提示未作为本次可靠性改动扩大处理。
- 新增 47 项用例：最长冷却、OI/补历史预算隔离、刷新后的权重与冷却、受限存储、公平补取、新币元数据、缺失身份/供应重验、真实旧值的可信性边界、失败槽共享、SQLite 关闭重开后保留值/原始缺口/冷却恢复。
- SQLite 实际成功→失败→关闭重开→恢复链路确认：原始 OI 历史为 `[95, null, 95]`，失败时显示缓存 95 且保持原时刻；原始合约数量缺口为 null，失败和恢复不重复制造告警，冷却中不额外采集。
- 本机 `server/reliability-ui-acceptance.ts` 使用真实 HTTP API、调度器及内存 SQLite，合成样本明确标注，失败由终端 `fail` 触发；`stop` 结束临时进程。专用入口仅限 127.0.0.1，生产入口不注册验收页面；CSP 还阻止估值页辅助行情流访问外部源。该脚本不进入前端 dist。
- 浏览器实测正常 +6% OI / +4% FDV 命中；模拟限流后 OI 覆盖率 0/1、命中 0、两项变化空缺，仍显示带旧时间的 106 和 $2.1K；刷新按钮禁用，后台健康返回相同冷却截止时间。冷却后新采样自动恢复，旧值标记撤销。
- 估值页同样验证失败时总 OI 为缺失而非缓存合计、提醒数 0、详情/表格旧值明确标记、短线比较暂停。390px 断点冷却提示可见，最终构建变化页无整页横向溢出；验收后关闭临时进程并恢复浏览器视口。

## 不作出的承诺

- 没有部署常驻云后台。GitHub Pages 只发布前端，默认仍是浏览器直连；关页或休眠会中断采集。
- 未完成 7 天连续采集、生产 PostgreSQL 负载/重启、共享 IP 多客户端压力或真实 418 封禁演练。没有为了测试主动冲击上游接口。
- FDV 需要可靠映射、供应量及价格；合理缺失仍保留空值。限流、网络异常和供应源缺失不会因保留展示值而变成“全量实时”。
